# Aspect-level sentiment: before / after evaluation

**What was compared.** How a keyword aspect mention gets its sentiment:

| Mode | Behaviour |
|---|---|
| `review` | every mention inherits the whole review's sentiment (the original behaviour) |
| `sentence` | only the sentence containing the keyword is scored with the same RoBERTa model (class probabilities averaged if several sentences mention the aspect); negated positive keywords ("not easy", "no value", "not worth") count as negative mentions |
| **`sentence+clause`** (**default**) | as `sentence`, but also cut at "but" / "however" / "although" / ";" and score only the keyword's clause (`ASPECT_SPLIT_CLAUSES = True` in `config.py`) |

**Data.** `reviews_171e719d99` (3,000 Datafiniti Amazon reviews). Aspects audited: `ux` and `price`.

**Which labels the numbers come from.** `data/eval/aspect_audit.csv` has 136 rows. Everything in the *Results from draft labels* sections below comes from **draft labels written by Claude** (`draft_label`), not from a person. Results from **human labels** live in their own section, generated by `scripts/eval_agreement.py` once `human_label` has been filled in; that section says so explicitly when it is empty. Until then, treat every precision figure as "agreement with Claude's labels".

The 136 rows are every mention that was negative in at least one mode: the original 75 review-level negatives (40 ux + 35 price), plus the 61 extra mentions that only the sentence variants flagged. The CSV's `neg_review` / `neg_sentence` / `neg_sentence_clause` columns record which modes count each row as negative. Labelling the extras too is what keeps the precision of the new modes honest; without them, mentions the new modes added would have been scored as if they didn't exist.

Label meaning: `genuine` = the reviewer criticises the aspect itself; `inherited` = the aspect is mentioned but not criticised (praise or neutral), the negativity comes from elsewhere in the review; `false_trigger` = the keyword matched something that isn't the aspect (idiom, a competitor's price, a build-quality "cheap", …). Precision = `genuine` / negative mentions.

One draft label was revised while labelling the second batch, for consistency: price #1938 ("Didn't work more than 4 months. Don't waste your money.") went from `inherited` to `genuine`, because an explicit "waste of money" is a value judgement whatever triggered it.

## What the draft-label numbers do and do not show

1. **Sentence scoring helps, mostly by finding more rather than by removing noise.**
   - UX precision rises 75% → 84% and genuine UX complaints found rise 30 → 42. The extra negatives (40 → 50) are mostly real complaints sitting inside otherwise positive reviews ("Love it. … my only complaint is that the interface is slow sometimes") that review-level scoring could never see.
   - Within the labelled pool (79 genuine mentions across both aspects), `review` finds 42 (53%), `sentence` 63 (80%), `sentence+clause` 67 (85%). That pool only contains mentions that were negative in some mode, so treat the recall figures as indicative, not absolute.
2. **Clause splitting is the default because it was better on every measure here**: price precision 41% → 57%, price genuine complaints found 20 → 25, one more known case fixed (5/7 vs 4/7), at a cost of one UX genuine mention (43 → 42). Setting `ASPECT_SPLIT_CLAUSES = False` restores plain sentence scoring; datasets analysed under the other setting are rebuilt automatically on load.
3. **Price is still mostly noise** (57%). See the limitation below.
4. **The impact ranking did not change, and shouldn't be read as settled.** ux is #1 and price #2 in every mode, and the closeness flag correctly says they are statistically close on raw counts (50 vs 44). But counting only labelled-genuine mentions, ux has 42 and price 25, so on this sample ux is a clearly bigger problem than the raw counts suggest, because price's negatives are mostly not price complaints.

## Known limitations

**Value idioms are misread by the general sentiment model.** The sentence-level scorer is the same general-purpose RoBERTa model used for whole reviews (trained on tweets). It reads many price/value expressions as negative even though they are praise or acceptance. Of the 44 price mentions that `sentence+clause` counts as negative, 25 are genuine complaints and **19 are not** (12 `inherited`, 7 `false_trigger`). Typical misreadings:

- "For the price I ended up getting it for, there's no arguement." (praise)
- "…but it's great, you can't beat the prices." (praise; "can't" and "no" read as negative)
- "I can't believe it's so cheap now." (praise)
- "Nothing speedy or top of the line, but what would one expect for the price." (acceptance)
- "Not that I have money to waste" (idiom unrelated to the product's price)

Negation handling only helps *positive-polarity* keywords such as "easy" or "worth"; "price" and "cost" are neutral words, so their sentiment is left entirely to the model.

**No price-specific idiom rules were added, by design.** Hand-written exceptions for individual phrases would overfit this one dataset and mask the model's real limitation. Genuine fixes would be a model that understands value expressions (fine-tuning on labelled aspect mentions, or a target-aware ABSA model) or human review of the flagged mentions, which the labelling tool now makes cheap. Until then, the low-confidence flag and the statistical-closeness note are the safeguards, and price complaint counts should be read as an upper bound.

Other limits:

- A sentence can still carry sentiment about something other than the keyword ("Not enough memory to hold kids apps" is storage, not apps).
- Small samples: 40–52 mentions per UX cell, 35–49 per price cell. A ±10-point swing in precision is within noise.
- One dataset (Amazon electronics). The lexicon was built for delivery/service language, which is part of why price and UX behave this way here.
- If the human labels turn out to differ from the drafts, the *Results from human labels* section above is the one to trust.

## Reproduce

```bash
python scripts/audit_aspect.py --export data/eval/aspect_audit.csv   # original 75 review-level negatives
python scripts/eval_aspects.py --append-unlabelled                   # add mentions only the new modes flag; refresh neg_<mode> flags
python scripts/eval_aspects.py                                       # prints the draft-label tables above
streamlit run scripts/label_app.py --server.fileWatcherType none     # label the rows (human_label)
python scripts/eval_agreement.py                                     # human-label precision + Cohen's kappa -> this document
```

`eval_aspects.py --out FILE` saves its tables to a file; don't point it at this document, which also holds the narrative.
